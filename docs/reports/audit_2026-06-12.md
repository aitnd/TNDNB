## 🔴 Lỗi Nguy kịch (Phải xử lý ngay)

### 1. Xung đột cấu hình ESLint gây treo và crash hệ thống quét code
*   **Triệu chứng:** Khi chạy `npm run lint`, hệ thống báo lỗi `Converting circular structure to JSON` từ file `.eslintrc.json` và lập tức dừng hoạt động với Exit Code 1.
*   **Nguyên nhân:** Dự án đang dùng song song cấu hình ESLint kiểu cũ (`.eslintrc.json`) và kiểu mới Flat Config (`eslint.config.mjs`). ESLint 9+ cố gắng parse cả hai dẫn đến vòng lặp vô hạn (circular reference).
*   **Hậu quả:** Anh không thể chạy công cụ kiểm tra lỗi code tự động để phát hiện các lỗi cú pháp hay biến rác trước khi deploy.
*   **Phác đồ điều trị:**
    1. Đồng bộ các thiết lập bỏ qua (`ignorePatterns`) của `.eslintrc.json` sang `globalIgnores` trong file [eslint.config.mjs](file:///d:/Antigravity/TNDNB/eslint.config.mjs).
    2. Xóa bỏ file cấu hình cũ [eslintrc.json](file:///d:/Antigravity/TNDNB/.eslintrc.json) để tránh xung đột.

## 🟡 Cảnh báo (Nên sửa để tránh rủi ro)

### 1. Thư viện Next.js phiên bản hiện tại chứa nhiều lỗ hổng bảo mật
*   **Triệu chứng:** `npm audit` phát hiện phiên bản Next.js hiện tại (`^14.2.35`) có nguy cơ bị tấn công từ chối dịch vụ (DoS), giả mạo yêu cầu từ phía máy chủ (SSRF) và chèn mã độc (XSS).
*   **Hậu quả:** Hacker có thể gửi các gói tin tùy biến làm sập server chạy Next.js Portal hoặc chèn script độc hại vào trang tin tức của anh.
*   **Phác đồ điều trị:** Nâng cấp Next.js lên phiên bản vá lỗi an toàn mới nhất của nhánh 14 (ví dụ `14.2.36+` hoặc bản 15/16 nếu chuẩn bị sẵn sàng cho việc nâng cấp lớn). Trước mắt nên chạy thử nâng cấp minor trong nhánh 14 để đảm bảo không lỗi giao diện.

### 2. Thư viện xử lý Excel `xlsx` (SheetJS) dính lỗi ReDoS và ô nhiễm nguyên mẫu (Prototype Pollution)
*   **Triệu chứng:** Thư viện `xlsx` có lỗ hổng bảo mật mức độ Cao (High).
*   **Hậu quả:** Nếu người dùng tải lên một file Excel được định dạng độc hại, hệ thống có thể bị treo cứng (Denial of Service) hoặc hacker có thể thay đổi các thuộc tính lõi của ứng dụng JavaScript.
*   **Phác đồ điều trị:** Thay thế bằng thư viện an toàn hơn như `exceljs` hoặc nâng cấp SheetJS thông qua registry chính thức của họ (không thông qua npm mặc định vì SheetJS bản miễn phí trên npm đã ngừng cập nhật từ lâu).

### 3. Thư viện `@grpc/grpc-js` có nguy cơ làm sập máy chủ
*   **Triệu chứng:** Phiên bản hiện tại có lỗ hổng gây crash server khi nhận request bị lỗi định dạng.
*   **Hậu quả:** Server API liên kết bị sập đột ngột khi có truy cập bất thường.
*   **Phác đồ điều trị:** Chạy lệnh `npm audit fix` để nâng cấp tự động lên phiên bản an toàn hơn mà không gây breaking changes.

## 🟢 Đề xuất tối ưu (Tùy chọn)

### 1. Đồng bộ hóa file cấu hình môi trường `.env` và `.env.local`
*   **Triệu chứng:** Hiện tại thư mục gốc có cả `.env` và `.env.local` chứa các thông tin giống hệt nhau.
*   **Hậu quả:** Dễ gây nhầm lẫn khi thay đổi cấu hình API key trong tương lai (sửa file này quên file kia).
*   **Phác đồ điều trị:** Giữ lại `.env.local` cho môi trường phát triển local và xóa `.env` thừa (hoặc chuyển `.env` thành file mẫu `.env.example` không chứa key thật để hướng dẫn người mới cấu hình).

### 2. Dọn dẹp các file rác và log build trong thư mục gốc
*   **Triệu chứng:** Có nhiều file log lỗi cũ như `lint_final.txt`, `tsc_errors.log`, `lint2_output.txt` chiếm dụng dung lượng và làm rối cây thư mục.
*   **Phác đồ điều trị:** Xóa bỏ hoàn toàn các file log thừa này vì chúng ta đã có cấu hình `.gitignore` chuẩn.
